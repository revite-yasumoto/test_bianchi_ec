# システム概要（横断ドキュメント）

本ドキュメントは個別の画面・機能の仕様書ではなく、複数の仕様書が前提とするサイト全体の構成を記述する横断ドキュメント。`## ソースファイル` を持たない。

## サイトの位置づけ

ビアンキECサイト（リニューアル）のデモサイト。オンライン決済は実装せず、支払いは銀行振込／代引きのみ。ゲスト購入不可（会員登録・ログイン必須）。海外発送は考慮しない。

## ブランド表記

画面上のブランド表記は `Bianchi` に統一する。参照元のUIモック（`docs/Markdown file UI mockups.zip`）は `VELOCE` と表記しているが、これは実装では使わない（決定済み）。注文番号の接頭辞は `BNC-`。

## 技術構成

`CLAUDE.md`「技術スタック」に従う（Laravel / Inertia.js / React / TypeScript / Tailwind CSS / MySQL 8 / SQLite in-memory テスト）。

- `config/app.php` の `timezone` は `Asia/Tokyo`。日時計算（配達予定日・掲載期間・ランキング公開タイミング等）はすべてこのタイムゾーンを前提にする。
- 開発・テスト実行は Docker コンテナ（`test_bianchi_ec_php` / `test_bianchi_ec_mysql`）で行う。ホストのWSLシェルに直接PHPは存在しないため、`docker exec test_bianchi_ec_php <command>` の形で実行する。

## 認証基盤（2ガード構成）

会員（フロント）と管理者（管理画面）は完全に独立した認証基盤を持つ。

| ガード | プロバイダ | 対象Model | セッションの独立性 |
|---|---|---|---|
| `web` | `users` | `App\Models\User` | 管理者としてログイン中でも会員ページには入れない |
| `admin` | `admins` | `App\Models\Admin` | 会員としてログイン中でも管理画面には入れない |

`users` テーブルと `admins` テーブルは完全に別。同一メールアドレスが両方に存在してもよい。管理者ごとの権限管理は実装しない（全管理者が全機能を利用できる）。

## 共通業務ルール

- **在庫の一元管理**: 在庫は商品マスタではなく在庫マスタ（`stocks`）で一元管理する。フロントの在庫表示は「在庫あり／在庫切れ」の二値のみで、在庫数は公開しない。
- **注文時スナップショット**: 注文確定後、会員情報・商品情報・配送先・送料設定・EC基本設定が変更されても、その注文の表示・金額は一切変わらない。詳細は `docs/order-snapshot.md`（注文確定を実装する単位で作成）。
- **SKUの有無による分岐**: 商品はSKUの有無で商品マスタ・商品詳細の挙動が変わる。SKUなし商品もサイズ・カラーが `null` のバリエーション1件を必ず持ち、カート・注文明細・在庫管理がSKUの有無で分岐しない構造にする。
- **会員の利用停止**: 会員の削除は実装しない。利用停止は `users.status = suspended`（休会）で表す。休会会員はログインできない。
- **管理者の保護**: 管理者は自分自身を削除できない。また管理者が1名になる場合は削除できない（管理画面に誰も入れなくなる状態を防ぐ）。
