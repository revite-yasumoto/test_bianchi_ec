# フロント 郵便番号からの住所検索

本書は**郵便番号から住所を引く処理**と**配送先モーダルの郵便番号入力欄**の正本。配送先の保存・入力値の検証は [docs/front/checkout.md](checkout.md) が正本であり、本書では再掲しない。

## 機能概要

- **対象画面・機能の目的:** 配送先の入力で、会員が郵便番号を入力した時点で都道府県・市区町村・町域を自動でセットし、住所入力の手間と誤入力を減らす。
- **URL / メソッド:**

| メソッド | パス | ルート名 | 内容 |
|---|---|---|---|
| GET | `/postal-codes/{postalCode}` | `postal-codes.show` | 郵便番号から住所を引く（JSONを返す。Inertiaのページ遷移ではない） |

- **アクセス権限・ミドルウェア:** `auth`（`web` ガード）と `throttle:60,1`。未ログインのアクセスはログイン画面へ遷移する。
- **本ドキュメントのスコープ:** 住所検索のエンドポイントと、配送先モーダル（`AddressModal`）の郵便番号入力欄の分割・自動セットの挙動。配送先の追加・更新・削除、および `postal_code` の保存形式と検証は [docs/front/checkout.md](checkout.md)・[docs/front/mypage-address.md](mypage-address.md) が正本。

## 使用テーブル

| テーブル | 用途 |
|---|---|
| `prefectures` | 外部サービスが返した都道府県名から `prefecture_id` を引く（読み取りのみ） |

定義は [docs/2_database.md](../2_database.md) が正本。本機能はテーブルへの書き込みを行わない。

## ユーザーインターフェース仕様（ワイヤーフレーム）

配送先モーダル内の郵便番号欄（PC幅・スマートフォン幅とも同じ並び。2欄は横並びのまま折り返さない）:

```
郵便番号 *
┌────────┐   ┌──────────┐
│  150   │ − │   0041   │
└────────┘   └──────────┘
住所を検索しています…                                  ← 検索中のみ表示
該当する住所が見つかりませんでした。住所を手入力してください。 ← 見つからない・通信に失敗したときのみ表示
```

- 郵便番号は前半3桁・後半4桁の2欄に分ける。数字以外の文字は入力の時点で取り除く（全角数字は半角に直す）。前半が3桁埋まると後半の欄へ自動でフォーカスを移す。
- 7桁が揃った時点で自動的に検索する。検索用のボタンは置かない。
- 検索中・検索結果の案内文は郵便番号欄の直下に出す。同じ位置にバリデーションエラーも出るため、バリデーションエラーがあるときはそちらを優先して表示する。
- 住所が見つかったときは、都道府県（プルダウン）と市区町村を検索結果で置き換え、番地は空のときだけ町域名を入れる。いずれの欄も自動セット後に会員が手で直せる。
- 住所が見つからないとき・通信に失敗したときは同じ案内文を出すだけで、入力済みの他の欄は変更しない。この状態でも住所は手入力して保存できる。

## インターフェース ＆ データロジック

### データ構造・型定義

エンドポイントのレスポンス（200）:

```ts
// resources/js/front/lib/postalCode.ts
type PostalCodeLookupResult = {
    prefecture_id: number | null;   // prefectures に一致する名前が無ければ null
    prefecture_name: string;
    city: string;                   // 市区町村
    town: string;                   // 町域（町域を持たない郵便番号では空文字）
};
```

| ステータス | 意味 | 本文 |
|---|---|---|
| 200 | 住所が見つかった | 上記の `PostalCodeLookupResult` |
| 404 | 該当する住所が無い／パスが7桁の数字でない | `{ "message": "該当する住所が見つかりませんでした。" }` |
| 429 | レート制限を超えた | Laravel 既定のレスポンス |
| 502 | 外部サービスに到達できない・応答が不正 | `{ "message": "住所を取得できませんでした。" }` |

郵便番号入力欄のProps:

```ts
// resources/js/front/Components/Checkout/PostalCodeField.tsx
type PostalCodeFieldProps = {
    id: string;
    value: string;                                  // 親が持つ `123-4567` 形式の値
    error?: string;                                 // サーバー由来のバリデーションエラー
    onChange: (postalCode: string) => void;         // `123-4567` 形式で親へ返す
    onResolved: (result: PostalCodeLookupResult) => void;  // 住所が引けたときだけ呼ぶ
};
```

### 入力値バリデーションルール

FormRequest は使わず、ルートパラメータの制約で受け付ける形を絞る。

| 項目 | ルール |
|---|---|
| `postalCode`（パスパラメータ） | 7桁の数字（`[0-9]{7}`）。ハイフンは含めない。合致しないパスはルートに一致せず404になる |

配送先そのものの検証ルール（`postal_code` を `\d{3}-?\d{4}` 形式で保存する等）は [docs/front/checkout.md](checkout.md) が正本。本機能は保存形式を変えない。

### 主要な処理フロー

**住所を引く（`PostalCodeLookupService`）**

1. キャッシュ（キー: `postal_code_lookup:` ＋ 郵便番号7桁、保持期間30日）に結果があればそれを返す。
2. 無ければ外部の郵便番号検索サービスへ問い合わせる（接続先・タイムアウト・保持期間は `config/services.php` の `postal_code_lookup`）。接続エラー・429・5xx のときだけ再送する（合計3回まで。再送しても結果が変わらない 4xx は繰り返さない）。待ち時間は応答に `Retry-After` があればその値を優先する。
3. 応答が得られない・応答の形式が不正・タイムアウトした場合は 502 を返す。この結果はキャッシュしない。
4. **外部サービスは HTTP 200 のまま応答本文の `status` でエラーを知らせる**ため、`status` が 200 以外の応答は該当なしと区別して 502 を返す（該当が無いのか、こちらの問い合わせ方が誤っているのかを取り違えないため）。この結果もキャッシュしない。
5. 該当が無い場合は 404 を返す。この結果もキャッシュしない（新設・変更された郵便番号が最大30日引けなくなるのを避けるため）。
6. 1つの郵便番号に複数の町域が紐づく場合は先頭の1件を採用する。
7. 都道府県名で `prefectures` を引いて `prefecture_id` を決める。一致する名前が無ければ `prefecture_id` を `null` にし、他の項目はそのまま返す。
8. 結果を30日キャッシュして返す。

**入力欄の挙動（`PostalCodeField`）**

1. 前半・後半の欄の入力から数字以外を取り除き、前半3桁・後半4桁に制限する。
2. 2欄を `123-4567` の形に結合して親へ返す（後半が未入力でも前半だけを親へ返す）。
3. 7桁が揃ったら住所検索を呼ぶ。同じ郵便番号を続けて引き直さない。
4. 検索中は案内文を出し、成功したら `onResolved` で親へ結果を渡す。
5. 見つからない（404）・失敗（429 / 502 / 通信エラー）のときは案内文を出すだけで、親の入力値は変えない。

**自動セット（`AddressModal`）**

1. `onResolved` で受け取った `prefecture_id` が `null` でなければ都道府県の選択を置き換える。
2. 市区町村を検索結果で置き換える。
3. 番地が空のときだけ町域名を入れる（入力済みの番地は上書きしない）。

## 業務ルール

- 外部サービスが停止していても配送先は登録できる。住所検索は入力補助であり、購入手続きを止めない。
- 1つの郵便番号に複数の町域が紐づく場合、どれが正しいかはサービス側の応答からは決められないため先頭を採用し、会員が手で直す前提とする。
- 郵便番号のデータを自社のDBに持たない。マスタの更新運用を持たない代わりに、外部サービスの可用性に依存する。
